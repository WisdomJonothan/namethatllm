## E3 prompt 聚类重建（transductive）

假设：测试集里同 prompt 的 18 段共享主题，可以把它们聚回组，再在组内做分配。

| 方法 | pairwise F1 | ARI |
|---|---|---|
| 阈值法（connected components） | 0.801（最好 thr=0.20，632 簇） | — |
| 层次聚类 average linkage | 0.810 | — |
| **层次聚类 complete linkage，n=150** | **0.914** | **0.913** |

在真标签上模拟组内重分配（中位组大小 18）：

| 配置 | BA |
|---|---|
| 直接 argmax（基线） | 0.3015 |
| 重建簇 + greedy | 0.3241（+0.0226） |
| **重建簇 + Hungarian** | **0.3875（+0.0860）** |
| 真簇 + greedy | 0.3330 |
| 真簇 + Hungarian | 0.4038（+0.1023，上限） |

用风格特征 OOF 重做：重建簇 + Hungarian **0.4316（+0.0838）**，上限 0.4486。救回 `gemini-3.8-flash` 0.253→0.480、`claude-fable-5` 0.114→0.295、`gpt-5.6-luna` 0.253→0.420。

**但公开实测（别人做的）是 −0.009~−0.017** —— 说明这个增益来自"我们知道有 18 类配对结构"这一先验，而隐藏测试每组只有 1–3 段，这个前提不成立。**结论：不做。**

脚本：`reconstruct_prompts.py`、`transductive_sim.py`。

> 教训：我一度给真类概率加常数做敏感性 sweep，那是标签泄漏，数字从 0.47 虚高到 0.71，已删。

## E4 A3 零方差伪影规则 → 否定

假设：某些模型有独一无二的排版怪癖，可以写成硬规则直接排除。

做法：47 个特征在官方 train 2,699 行上按模型统计。

结果：**没有任何一条**满足 `p_own ≥ 0.50 且其他 17 个 ≤ 0.10`（最强 gap 仅 0.04，`colon_space → kimi-k3`）；反向的"某模型从不使用"硬 veto **也一条都没有**。纯排版特征训 LR 在 eval_v2 上 BA 仅 0.1716。

**结论：硬规则路线放弃。** 公开那几条手写规则要么是软调参，要么作用在更细粒度的模式上。

脚本：`artifact_rules.py`；输出：`results/artifact_rules.json`、`results/artifact_veto.csv`。

## E5 A1 prompt 固定效应 → 负结果

假设：把同组 18 行的特征减去组均值，抹掉主题、只留风格。

结果（eval_v2 上，C=0.5/2/8）：

| 处理 | BA |
|---|---|
| 原始特征 | 0.1617 / 0.1636 / 0.1556 |
| 组内中心化 | 0.1429 / 0.1436 / 0.1424 |
| Δ | **−0.0188 / −0.0200 / −0.0132** |

accuracy 反而从 0.144 升到 0.173 —— 被推向多数类，正是 BA 不想要的。

**结论：不做。**

脚本：`prompt_fe_probe.py`。

## E6 A4 BA 最优决策层 → 小正信号

理论：balanced accuracy 的 Bayes 规则是 `argmax p(x|y) = argmax p(y|x) / p_train(y)`，而 Sinkhorn 是把预测边缘拉向测试先验，两者目标不同。

弱模型实测：

| 做法 | BA | Δ |
|---|---|---|
| 直接 argmax | 0.1716 | — |
| 纯先验校正 | 0.1716 | **+0.0000** |
| 在 train 上拟合 18 个类别偏置 | 0.1772 | **+0.0056** |
| 在测试集上拟合（交叉拟合，不可部署） | 0.2159 | +0.0443 |

**结论：值得在真集成上试，零 GPU 成本；但先验校正本身没用，需要拟合偏置。**

脚本：`logit_adjust.py`。

## E8 独立集的分布差异（为什么 0.478 ≠ 0.716）

| | 官方 train | eval_v2 |
|---|---|---|
| 词数中位数 | 101 | 134（塌缩类到 193） |
| 含 `**粗体**` | 0% | 56–69% |
| 含括号 | 1–5% | 32–48% |

同一 TF-IDF 模型：train 的 prompt 分组 OOF **0.348**，eval_v2 **0.146**，eval_v2 内部 CV **0.663**。

按体裁筛选子集（≤160 词、无 Markdown）后 BA 从 0.164 降到 0.139 —— 说明差异不只是表层格式。

**结论：eval_v2 只能当"回归哨兵"，不能当 LB 代理。任何改动必须在官方 train 的 prompt 分组 OOF 上符号一致才算证据。**

## E9 最后一层后处理是域外负贡献

最终 `final-logits.npz` 的 argmax 在 eval_v2 上 0.5017，而写进 `submission` 的预测 0.4783，两者只有 95% 行一致 —— 约 5% 的行被最后一步改掉了，净损 0.023。

**结论：这套后处理对竞赛分布过拟合。域内可能是 +0.012，域外是负的。**

## E11 带空格破折号规则的离线重放

保留 public 0.716 的 v3。eval_v2 的 3,350 行重放与诊断输出逐行一致。cell 48 前后有 166 行最终标签不同。撤销整个阶段会救回 99 行、误伤 18 行。重点追查的 GPT-5.5、Sonnet-5 转两款 Opus 的 59 行均触发了带空格破折号规则。

| 诊断配置 | eval_v2 BA | 相对上一行 |
|---|---:|---:|
| cell 48 之前（native 融合） | 0.5017 | — |
| 仅残差分支，只覆盖非 GLM 预测（代码实际行为） | 0.4991 | −0.0026 |
| 残差施加到全部行（假设情形，代码不会这样做） | 0.4984 | −0.0033 |
| 残差分支 + 排版规则 2/3，不含规则 1 | 0.4961 | −0.0056 |
| 出厂版（残差 + 规则 1/2/3） | 0.4783 | −0.0234 |
| 规则 1 仅在当前预测为 Claude 时触发 | 0.4870 | — |

归因时不能把 −0.0056 整个算给残差：0.4961 那一行里规则 2/3 仍各触发 1 次和 10 次。残差分支自身是 −0.0026；规则 2/3 单独是 −0.0030；规则 1 单独约 −0.0178。0.4984 是把残差施加到全部行（含 GLM）的假设数字，代码实际只覆盖非 GLM 行，因此不能当作"残差步骤的 BA"。

官方训练集中只有两款 Opus 和两款 GLM 出现该记号。外部集的 GPT-5.5 则有 29% 使用它。仅在 Claude 预测上触发会同时减少错误覆盖和正确救回。例如，真值为 Opus 但初判为 GPT 的文本可能失去一次纠正机会。现有对照只支持域外收益，竞赛增益和上限仍待测定。

决策：保留原规则。本轮结束。若以后取得来源接近竞赛的盲测数据及完整流水线的规则前预测，只在原版和变体预测不同的行上核算各类召回的增减。留存证据为工作目录 results 下的 apex_v2_replay.json 和 apex_v2_variants.json。

## E12 GLM 似然阶段的融合算法问题（stage3 诊断跑批）

stage3 内核（`repro/diag_v3.ipynb`）在 eval_v2 上跑完整个 v3 流水线，GPU T4×2 耗时 23,749.7 s，落盘了六成员分项 LP、Apex 前预测与两款 GLM 的逐 token 证据。

**六成员对账**：`diag_lp_members.npz` 实有 16 个数组（6 个读者 + 各自 `_twin`/`_gauss` + `tfidf`/`svc4`/`distort`）。全部相加与 `diag_lp.npy` 的最大绝对差 **3.4e-6**，即融合输入确实等于成员 LP 之和。需要注意的是 `--tfidf_w 0 --svc_w 0 --distort_w 0` 并未把它们排除出求和（`svc4` 最大幅值 67.6）。

**Apex（cell 48）**：按 ID 对齐两个真实 parquet 后，Apex 前 BA **0.52065** → 最终 **0.49941**，翻转 **239** 行（救回 30、改错 104、其余 105 前后都错）。与 E11 的方向一致。

> 更正：本文件早先写的 0.5206 → 0.5017 / 251 次翻转是错的。`scripts/analyze_stage3.py` 当时把 `final-logits.npz` 的 argmax 当成 Apex 后的预测，而该文件存的是 `v1_stage.py` 读取的底座 logits（每次 `write()` 覆盖，最后一次在 native 之后），所以它测的是"从 V1 输出回看输入"。脚本已改为用 `diag_pred.parquet` 作为 Apex 后预测。

**GLM 阶段**：`changed=0.0749 < 0.25`，保护性断言未触发；覆盖 16.5%（553/3,350，`mass_threshold=0.361`）是时间卡住的，不是预算上限（`flash 1449.5 s`、`glm53 2455.8 s`、`temperature 1.7155`、`weight 0.8744`）。

在**真实底座**（V1 输入，BA 0.50173）上按 ID 对齐重放三种融合，全部走完同一 Apex：

| 变体 | Apex 前 BA | Apex 后 BA | 最终相对出厂 |
|---|---:|---:|---:|
| 出厂加性 `argmax(zl + 0.874·ll)` | 0.52065 | 0.49941 | — |
| 质量保持、两类内部重分（553 行全部） | **0.52923** | **0.50611** | **+0.00670** |
| 只对"底座赢家已是 GLM"的行重分（441 行） | 0.52299 | 0.49989 | +0.00048 |

重放校验（`scripts/glm_blend_final.py`，`W=0.8743927164`）：出厂重建与 `pred_pre_apex.parquet` **3350/3350** 一致；继续重放 Apex 与 `diag_pred.parquet` **3350/3350** 一致。此前 `scripts/replay_v1_blend.py` 已删除：布尔掩码 `z2[sel_mask] += w*ll` 未按 ID 对齐、"质量保持"在 18 类上归一化再取两类会丢质量、oracle 对非 GLM 行使用真值。

**增益来源（`scripts/glm_blend_decomp.py`）**：与 Apex 前相比，+0.00695 全部来自两款 GLM 的召回（`glm-5.3-flash` 0.5432→0.6481，+17 篇；`glm-5.3` 0.6010→0.6212，+4 篇），其余 16 类合计 **−0.00054**。只做"两版判别"的受限变体几乎为零（+0.0005），所以收益不是"更会分版本"，而是**让 GLM 总概率按版本比例重分后反超非 GLM 赢家**：98 行跨族进入 GLM（其中真值确为 GLM 41 行），10 行离开（真 GLM 5 行）。按来源拆：corpus 2,941 行 +0.0042，harvest 409 行 +0.0557（该子集只有 7 篇闪光版，2 篇翻转，方差极大）。按 prompt 成组重采样 400 次：均值 **+0.00676**，95% 区间 **[+0.00245, +0.01159]**，全部为正。

**限制**：弱读者底座上的 +0.024 不迁移到真实底座；在真实底座上出厂融合本身已贡献 +0.01892，改版增量是 +0.0086（Apex 前）/ +0.0067（Apex 后）。且增益依赖"底座对 GLM 总概率的判断"，是外部语料分布上的性质；保持总概率不保证不跨族改判，而本变体的收益正是来自跨族改判。不能把它加到公榜 0.716 上。

证据：`results/stage3_analysis.json`、`results/glm_blend_final.json`、`results/glm_blend_decomp.json`、`runs/diag3/`。

## 为什么 v5 暂不加读者否决层

在 eval_v2 的 3,350 行上重放完整 Apex。出厂版和 v5 最终有 104 行分歧，v5 单独正确 32 行，出厂单独正确 12 行，两边都错 60 行。全部接受 v5 相对出厂的 BA 增量为 0.006697。否决后回到出厂，对出厂的增量为零。重复 40 次按 prompt 分折，平均增量为 base_diff 0.005933、DeBERTa 0.006354、n14b_clean 0.006913、原始 reader_min 0.006619、成员 softmax 后的 reader_min 0.006672。n14b_clean 在决定性行上的 AUC 为 0.766，额外平均收益仅 0.000216。重排复用同一批样本，仍需独立数据验证。reader_min 对成员权重尺度敏感，现有证据不足以支持六成员共识的解释。保留简单融合等待正式提交结果。

补充一条同批数据的旁证（`scripts/glm_family_probe.py`、`results/glm_family_probe.json`）：在入选的 553 篇里，真 GLM 258 篇、非 GLM 295 篇，底座 GLM 质量在中位数以上的困难负例 135 篇。两款 GLM 的较优自似然对"是不是 GLM"的全样本 AUC 只有 0.512、按底座质量分 5 层后的层内 AUC 0.511；token 熵、surprise、fdg 都在 0.48–0.51。自似然只区分得了两款 GLM 属于哪一版（258 篇真 GLM 上 AUC 0.99），不能充当家族证据。该探针最初报的 `reader_min` 层内 AUC 0.637 已证伪：`diag_lp_members.npz` 存的是乘过成员权重的 log 贡献，`exp(3·log p)=p³`，取最小值实际在比输出尺度；逐成员 softmax 后降到 0.576、按主权重还原后 0.500，且 533/553 篇的最小值来自 DeBERTa 或 `n14b_clean`。

复现：`python scripts/glm_flip_veto.py` 打印 104 行分歧与 32/12/60 的分解，`python scripts/glm_flip_veto_stability.py` 做 40 次折重排；逐行分数在 `results/glm_flip_rows.npz`。


## E13 — 质量保持 GLM 融合上了公榜：没有兑现（2026-11-23）

**改法**：v1 阶段的 GLM 融合从「加性 `z2[sel] += w·ll`」改成「先保留两款 GLM 的总质量 m，再在两版之间用自似然 softmax 重分」，并加守卫 `changed_mass <= max_changed(0.25)`，超限回退加性。载荷 sha `7820541658971df890fdeb05451bfd0458daf81628e1893c916781222d1056c0`，notebook `repro/prod_mass.ipynb`，内核 `ntl-v5-mass-preserving-glm-blend`。

**本地（eval_v2，3,350 行）**：出厂 0.52065 → 0.49941；质量保持 0.52923 → 0.50611，净 **+0.00670**；prompt 成组 bootstrap 400 次 95% 区间 [+0.00245, +0.01159]，全为正。

**公榜**：

| 提交 | 内容 | public |
|---|---|---:|
| ref `58689652`（v3） | 出厂加性融合 | **0.716** |
| ref `58763287`（v5） | 质量保持融合 | 0.705 |

**读法**：−0.011 与同码重跑噪声（±0.01）同量级，不能据此判定"质量保持有害"；但**方向与本地 +0.0067 相反**，唯一能确定的结论是：eval_v2 上量到的这点增量不能迁移到隐藏集。

**为什么没做成的可能原因**（未验证）：本地增益的主要机制是「GLM 总概率按版本比例重分后反超非 GLM 赢家」——eval_v2 里 98 行跨族进入 GLM（真 GLM 41 行），而隐藏集的 GLM 占比与文体都和外部语料不同；一旦"底座对 GLM 总概率的判断"在竞赛域上更保守，跨族重分就更可能伤而不是救。

**决定**：不部署 v5，final 保留 v3 的 0.716。以后所有后处理改动必须在公榜上做单变量对照，不能只凭 eval_v2；一次公榜对照的成本是一次提交额度和约 8 小时排队。

**未取到的证据**：隐藏集重跑的 `v1/report.json`（含 `blend`/`changed_mass`/`n_selected`）不在内核 Output 里（那里只有 FAST_COMMIT 的交互产物），提交记录也不暴露重跑日志。因此"守卫是否回退到加性"只能由 `changed_mass≈3%` 远低于 0.25 推断，未经实测确认。

## E14 作者条件似然探针（Qwen3-4B，服务器 3090）

**问题**：v3 底座在 eval_v2 上的候选覆盖是 top1 0.5017 / top2 0.6745 / top3 0.7782 / top5 0.8928，"第一名与真作者同家族" 0.7862。若有一个共享的、以候选作者为条件的预训练 LM 能区分作者，就有可能在第二层重判。本实验检验该假设是否成立。

**设置**：服务器 `/tmp/reteco-qwen4b.JMpBpsvH`（Qwen3-4B，bf16，3 分片 8G），`ntllm/.venv`（torch 2.7.0+cu126，transformers 5.22.2），单卡 3090。前缀 `Written by {author}:\n\n`，正文截 320 token，取正文平均 token log-prob，argmax 判别。两组三选一：GPT `luna/terra/sol`（eval_v2 632 篇）、`claude-fable-5/glm-5.3/glm-5.3-flash`（560 篇）。

**结果**

| 组别 | 原始 acc | 去每作者常数偏移 | 说明 |
|---|---:|---:|---|
| GPT 三兄弟（632） | 0.3196 | 0.3687 | 塌向 `sol`（召回 0.836），luna 0.005 / terra 0.033 |
| Fable/GLM（560） | 0.3607 | 0.3929 | 塌向 `glm-5.3`（召回 0.889） |

原始用法失效的原因是前缀先验：三位候选的平均分只差 0.022 nats（−3.459 / −3.458 / −3.437），一个常数就决定全部预测。去掉每位作者在整批文本上的均分（不用标签）才露出信号。

**家族判别（全量 3,350 篇）**：真作者属于该三人的 632 篇 vs 其余 2,718 篇，以"被判定为家族内"计 AUC = **0.291**（反向，家族内文本的似然反而更低）；只看"底座说不是该家族"的 2,728 篇，AUC = **0.267**。

**第二层重排**：在底座已判对家族的 516 篇上，底座成员 acc **0.5504**，探针 0.3682（救回 89、改错 183）。

**结论**：预注册三条判据全部不成立——①不超过分类头基线（0.40/0.38 官方、0.35/0.33 外部）；②跨家族没有信号且方向相反；③家族边界不存在。作者条件似然这条线关闭，停止 18 类候选生成。附带可复用事实：服务器 4×3090（GPU2/3 常空）、`ntllm/.venv` 的 transformers 5.22.2 可直接吃 `dtype=` 参数。

## E15 两条候选路线：弱单模强互补 vs 成对比较器（2026-11-24）

**问题**：在官方 train 上（prompt 分组五折、同题同折），检验两条独立路线。①独立 18 类作者模型能否补充 v3 的读者组；②训练一个真正比较"同题两篇谁是谁"的候选比较器（luna/terra、luna/sol）。前置检查确认 v3 的折外候选拿不到（读者权重由第三方在竞赛 train + 公开池上训，无法保证折外），所以都改用自训折外底座，结论标注为"相对自训底座"。

**底座与嵌入**：底座 char_wb(3–5)+word(1–2) TF-IDF+48 维风格特征 LR，OOF 0.3478；嵌入用 Qwen3-Embedding-0.6B（last-token pooling + L2 归一，bf16，320 token）在服务器抽 2,699×1024。

**路线①：编码器**

| 配置 | fold 外 BA |
|---|---:|
| 冻结嵌入 + LR（C=1） | 0.1641 |
| 编码器 + 18 类头，全参微调（lr 3e-5、4 epoch、bs16） | 0.3090 |
| 同上，fold 0 | 0.3222 |
| **与底座概率融合 w=0.40** | **0.3819（+0.0341）** |

互补性：两模型预测只有 **29.3%** 相同；底座 1,760 个错里编码器改对 **411（23.4%）**。融合权重不是尖峰（0.35→0.3797、0.45→0.3793）。逐类增益集中在非 GPT 家族：`claude-opus-4-6` .533→.640、`claude-opus-5` .573→.700、`gemini-3.1-pro` .713→.767、`gemini-3.8-flash` .253→.367、`kimi-k3` .260→.313；GPT-5.6 三兄弟基本不动（sol .213→.193、terra .173→.167）。

**路线②：成对比较器**（LR on `concat[e_text, e_a, e_b]`，只在该对触发时改判，对照 = 同样改判数量但按原始两类分差挑）

| 底座 | 对 | 触发 | 比较器 Δ | 等改判对照 Δ |
|---|---|---:|---:|---:|
| TF-IDF+风格 0.3478 | luna/terra | 76 | +0.0026 | +0.0007 |
| 同上 | luna/sol | 45 | −0.0007 | +0.0004 |
| 纯 TF-IDF 0.3015 | luna/terra | 100 | −0.0007 | +0.0007 |
| 同上 | luna/sol | 57 | +0.0007 | −0.0004 |
| 融合底座 0.3819 | luna/terra | 58 | +0.0011 | +0.0000 |
| 同上 | luna/sol | 44 | −0.0007 | −0.0019 |

换三种底座符号来回翻、幅度 ±0.003，比较器始终不优于等改判对照 → 路线②关闭（与 E5 的池专家结论一致：它学的是"把 luna 边界往回收"）。

**加试：同题硬负例三元组**（批内每组 = anchor + 同作者异题正例 + 同题异作者负例，`L = CE + 0.5·relu(0.3 + d_pos − d_neg)`，余弦距离）

| 配置（fold 0） | BA |
|---|---:|
| 原版（bs16、320 token、4 epoch、约 540 步） | 0.3222 |
| 分组批（3 篇/组、256 token、7 epoch、约 620 步）+ 三元组 | 0.2278 |
| 同上但 λ=0（同步数纯 CE 对照） | 0.2704 |

三元组本身有害（0.2704→0.2278）：CE 在把"同题不同作者"的嵌入拉近（共享主题），三元组与之对抗，日志里 CE 下降变慢而 trio loss 反而上升。分组小批与短上下文本身也掉点（0.3222→0.2704）。

**结论**：路线②与同题难负例增强都关闭。路线①的价值是"弱单模 + 强互补"，但要在 0.716 流水线上兑现，需把它作为第 7 个读者接入并重跑诊断——本实验不做该判断（无本地 in-domain holdout，见 E13 的教训）。服务器侧可复用：`/homeC/wujiaheng/ntllm/.venv` + `models-qwen3-emb06`；`AutoModel` 会带 LM 头，24G 卡上 72×320 token 就会 OOM，需换 `Qwen3Model` 并保持批 ≤24×320。
