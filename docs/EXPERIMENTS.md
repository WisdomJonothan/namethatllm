## E3 prompt 聚类重建（transductive）

假设：测试集里同 prompt 的 18 段共享主题，可以把它们聚回组，再在组内做分配。

| 方法 | pairwise F1 | ARI |
|---|---|---|
| 阈值法（connected components） | 0.801（最好 thr=0.20，632 簇） | — |
| 层次聚类 average linkage | 0.810 | — |
| **层次聚类 complete linkage，n=150** | **0.914** | **0.913** |

在真标签上模拟组内重分配（中位组大小 18）：

| 配置 | BA |
|---|---|
| 直接 argmax（基线） | 0.3015 |
| 重建簇 + greedy | 0.3241（+0.0226） |
| **重建簇 + Hungarian** | **0.3875（+0.0860）** |
| 真簇 + greedy | 0.3330 |
| 真簇 + Hungarian | 0.4038（+0.1023，上限） |

用风格特征 OOF 重做：重建簇 + Hungarian **0.4316（+0.0838）**，上限 0.4486。救回 `gemini-3.8-flash` 0.253→0.480、`claude-fable-5` 0.114→0.295、`gpt-5.6-luna` 0.253→0.420。

**但公开实测（别人做的）是 −0.009~−0.017** —— 说明这个增益来自"我们知道有 18 类配对结构"这一先验，而隐藏测试每组只有 1–3 段，这个前提不成立。**结论：不做。**

脚本：`reconstruct_prompts.py`、`transductive_sim.py`。

> 教训：我一度给真类概率加常数做敏感性 sweep，那是标签泄漏，数字从 0.47 虚高到 0.71，已删。

## E4 A3 零方差伪影规则 → 否定

假设：某些模型有独一无二的排版怪癖，可以写成硬规则直接排除。

做法：47 个特征在官方 train 2,699 行上按模型统计。

结果：**没有任何一条**满足 `p_own ≥ 0.50 且其他 17 个 ≤ 0.10`（最强 gap 仅 0.04，`colon_space → kimi-k3`）；反向的"某模型从不使用"硬 veto **也一条都没有**。纯排版特征训 LR 在 eval_v2 上 BA 仅 0.1716。

**结论：硬规则路线放弃。** 公开那几条手写规则要么是软调参，要么作用在更细粒度的模式上。

脚本：`artifact_rules.py`；输出：`results/artifact_rules.json`、`results/artifact_veto.csv`。

## E5 A1 prompt 固定效应 → 负结果

假设：把同组 18 行的特征减去组均值，抹掉主题、只留风格。

结果（eval_v2 上，C=0.5/2/8）：

| 处理 | BA |
|---|---|
| 原始特征 | 0.1617 / 0.1636 / 0.1556 |
| 组内中心化 | 0.1429 / 0.1436 / 0.1424 |
| Δ | **−0.0188 / −0.0200 / −0.0132** |

accuracy 反而从 0.144 升到 0.173 —— 被推向多数类，正是 BA 不想要的。

**结论：不做。**

脚本：`prompt_fe_probe.py`。

## E6 A4 BA 最优决策层 → 小正信号

理论：balanced accuracy 的 Bayes 规则是 `argmax p(x|y) = argmax p(y|x) / p_train(y)`，而 Sinkhorn 是把预测边缘拉向测试先验，两者目标不同。

弱模型实测：

| 做法 | BA | Δ |
|---|---|---|
| 直接 argmax | 0.1716 | — |
| 纯先验校正 | 0.1716 | **+0.0000** |
| 在 train 上拟合 18 个类别偏置 | 0.1772 | **+0.0056** |
| 在测试集上拟合（交叉拟合，不可部署） | 0.2159 | +0.0443 |

**结论：值得在真集成上试，零 GPU 成本；但先验校正本身没用，需要拟合偏置。**

脚本：`logit_adjust.py`。

## E8 独立集的分布差异（为什么 0.478 ≠ 0.716）

| | 官方 train | eval_v2 |
|---|---|---|
| 词数中位数 | 101 | 134（塌缩类到 193） |
| 含 `**粗体**` | 0% | 56–69% |
| 含括号 | 1–5% | 32–48% |

同一 TF-IDF 模型：train 的 prompt 分组 OOF **0.348**，eval_v2 **0.146**，eval_v2 内部 CV **0.663**。

按体裁筛选子集（≤160 词、无 Markdown）后 BA 从 0.164 降到 0.139 —— 说明差异不只是表层格式。

**结论：eval_v2 只能当"回归哨兵"，不能当 LB 代理。任何改动必须在官方 train 的 prompt 分组 OOF 上符号一致才算证据。**

## E9 最后一层后处理是域外负贡献

最终 `final-logits.npz` 的 argmax 在 eval_v2 上 0.5017，而写进 `submission` 的预测 0.4783，两者只有 95% 行一致 —— 约 5% 的行被最后一步改掉了，净损 0.023。

**结论：这套后处理对竞赛分布过拟合。域内可能是 +0.012，域外是负的。**

## E11 带空格破折号规则的离线重放

保留 public 0.716 的 v3。eval_v2 的 3,350 行重放与诊断输出逐行一致。cell 48 前后有 166 行最终标签不同。撤销整个阶段会救回 99 行、误伤 18 行。重点追查的 GPT-5.5、Sonnet-5 转两款 Opus 的 59 行均触发了带空格破折号规则。

| 诊断配置 | eval_v2 BA | 相对上一行 |
|---|---:|---:|
| cell 48 之前（native 融合） | 0.5017 | — |
| 仅残差分支，只覆盖非 GLM 预测（代码实际行为） | 0.4991 | −0.0026 |
| 残差施加到全部行（假设情形，代码不会这样做） | 0.4984 | −0.0033 |
| 残差分支 + 排版规则 2/3，不含规则 1 | 0.4961 | −0.0056 |
| 出厂版（残差 + 规则 1/2/3） | 0.4783 | −0.0234 |
| 规则 1 仅在当前预测为 Claude 时触发 | 0.4870 | — |

归因时不能把 −0.0056 整个算给残差：0.4961 那一行里规则 2/3 仍各触发 1 次和 10 次。残差分支自身是 −0.0026；规则 2/3 单独是 −0.0030；规则 1 单独约 −0.0178。0.4984 是把残差施加到全部行（含 GLM）的假设数字，代码实际只覆盖非 GLM 行，因此不能当作"残差步骤的 BA"。

官方训练集中只有两款 Opus 和两款 GLM 出现该记号。外部集的 GPT-5.5 则有 29% 使用它。仅在 Claude 预测上触发会同时减少错误覆盖和正确救回。例如，真值为 Opus 但初判为 GPT 的文本可能失去一次纠正机会。现有对照只支持域外收益，竞赛增益和上限仍待测定。

决策：保留原规则。本轮结束。若以后取得来源接近竞赛的盲测数据及完整流水线的规则前预测，只在原版和变体预测不同的行上核算各类召回的增减。留存证据为工作目录 results 下的 apex_v2_replay.json 和 apex_v2_variants.json。

## E12 GLM 似然阶段的融合算法问题（stage3 诊断跑批）

stage3 内核（`repro/diag_v3.ipynb`）在 eval_v2 上跑完整个 v3 流水线，GPU T4×2 耗时 23,749.7 s，落盘了六成员分项 LP、Apex 前预测与两款 GLM 的逐 token 证据。

**六成员对账**：`diag_lp_members.npz` 实有 16 个数组（6 个读者 + 各自 `_twin`/`_gauss` + `tfidf`/`svc4`/`distort`）。全部相加与 `diag_lp.npy` 的最大绝对差 **3.4e-6**，即融合输入确实等于成员 LP 之和。需要注意的是 `--tfidf_w 0 --svc_w 0 --distort_w 0` 并未把它们排除出求和（`svc4` 最大幅值 67.6）。

**Apex（cell 48）**：Apex 前 BA 0.5206 → 最终 0.5017，翻转 251 行（救回 24、改错 82、其余 145 双错）。与 E11 的方向一致。

**GLM 阶段**：`changed=0.0749 < 0.25`，保护性断言未触发；覆盖 16.5%（553/3,350，`mass_threshold=0.361`）是时间卡住的，不是预算上限。

在同一读者底座（BA 0.48515）上重放四种融合，全部在 eval_v2：

| 变体 | BA | 真 GLM 行判定准确率 |
|---|---:|---:|
| 仅读者 | 0.48515 | 0.311 |
| 出厂版 `argmax(zl + 0.874·ll)` | 0.48469（−0.0005） | 0.303 |
| 质量保持（保留该对总概率，只在两版间重分） | 0.50914（+0.0240） | 0.503 |
| 质量保持 + 自似然二选一 | 0.50946（+0.0243） | 0.508 |
| 该对内部完美判别（上限） | 0.52500（+0.0398） | 0.564 |

出厂版把 GLM 的 18 类意见直接加进全部 logits，与其余 16 个类竞争；意见判错时会抢走别的类的质量，净效果接近零。质量控制式不会跨类移动质量，门槛从 0.1 扫到 0.8 BA 只变 0.001，因此安全。

自似然本身能分这两版（258 行真 GLM 上 AUC 0.99、正确率 91%），但管线用的是"两模型特征 → 54 维逻辑回归 → 18 类意见"，二选一并非主因。

**限制**：+0.024 是加在只有读者的弱底座上；真实管线 v1 之前的底座约 0.52，上限会缩小。结论应表述为"融合算法有可测的算法缺陷"，而不是"LB 会涨 0.024"。

证据：`results/stage3_analysis.json`、`results/v1_blend_replay.json`、`results/glm_pair_reblend.json`、`runs/diag3/`。
