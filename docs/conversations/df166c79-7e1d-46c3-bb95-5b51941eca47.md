**1. Guarded Fable Return 门控**
- 技术点：先用 stack 分类，再用 GLM 似然阶段；当 stack 选 GLM、似然阶段却让 claude-fable-5 胜出，且 fable 相对更强 GLM 兄弟的 margin 在似然后增加 ≥0.30、最终 ≥0.25 时，就保留 Fable 的判定，规则放在排版过滤器之前执行。
- 声称增益：public LB 从 0.716 升到 **0.719**（+0.003）；作者自述上一版同类门控只与 0.706 的对照打平，因此这个增益落在重跑噪声范围内。
- 来源：https://www.kaggle.com/code/dennis6886/glm-user-prefix-guarded-fable-return
- 复现成本：纯后处理，复用父 notebook 的权重与特征，<1 T4 小时；前提是你已有一条 ~0.70 级、且 fable-5 召回极低（0.456）的 stack。

**2. user-prefix 似然特征重算（本次最大的单点增益）**
- 技术点：给每段文本前置还原后的原始请求 `[gMASK]<sop><|system|>Reasoning Effort: Low<|user|>Write a single paragraph of about {n_words} words, with no title or headings.<|assistant|><think></think>`，用 GLM-5.3 与 GLM-5.3-Flash 重算 2,699 条 train 特征，重拟合 54 维、18 类逻辑回归，只混入 GLM mass 前 30% 的文本，公式 `argmax(z + (W/T')·log p_member)`，W=1.5。
- 声称增益：按 prompt 分组 OOF **0.7028 → 0.7168（+0.014，CI90 [+0.006,+0.021]）**；recall glm-5.3-flash 0.647→0.707、glm-5.3 0.627→0.680、fable-5 0.456→0.503；public LB 0.701 → 0.716 与 0.715（两次同代码）。
- 来源：https://www.kaggle.com/code/estopadilla/0-716-robust-glm-5-3-likelihood-user-prefix/versions/5
- 复现成本：两模型重算 train 特征约 **5.6 T4 小时**（分两次跑）；每次提交的推理阶段约 50 分钟；另需 160 token 截断与 IQ3_XXS 分段权重。前缀只多约 17 token，几乎不增算力。

**3. GLM 似然的"超时就截断"调度器（消除灾难性回退）**
- 技术点：文本按 glm-5.3+flash 的 stack 概率降序送入；每跑完一个 layer segment 就按已耗时外推剩余时间，若剩余量在 10% margin 内装不下，就只保留前 m 条并重写 token 文件（hidden state 不动，分数与全跑完全一致），GLM-5.3 只在 Flash 跑完的文本上继续；剩不到 50 条则直接退回 stack 答案。
- 声称增益：不产生 +x，而是把同代码 6 次提交的 **0.682–0.694 分布收敛到 0.716/0.715**（0.682 正好等于"没有该阶段"的 stack，最坏情况被消掉，相当于救回 +0.012）。
- 来源：https://www.kaggle.com/code/estopadilla/0-716-robust-glm-5-3-likelihood-user-prefix/versions/5
- 复现成本：纯代码逻辑，<1 T4 小时开发；每次 run 的预算已经内嵌在 540 分钟上限里，T4 双卡速度 ±30% 波动正好被吸收。

- 声称增益：Qwen3-1.7B+LoRA、每类恰好 2,500 条（共 45k）、2 seed、在 2,699 条真 train 上评：raw 0.466 → **去硬垃圾 0.474（+0.009）→ 再去错体裁 0.493（+0.027）**；脏度与增益 Spearman 0.64，kimi-k3 recall +16 点。
- 来源：https://www.kaggle.com/competitions/name-that-llm/discussion/753779
- 复现成本：CPU 清洗数小时；验证消融在 T4x2 上约 **2–4 GPU 小时**（1.7B、45k 段、1 epoch ×2 seed）。

**7. Open Pool v14 保真度校准（按"像不像真 train"筛池子）**
- 技术点：只在 2,699 条真 train 上训 TF-IDF+LR（按 prompt 5 折），用 33% balanced acc 当固定标尺去打分池子里的每一段，算出各家族识别率比值；据此发现 kimi-k3 池子里只有 `gen_reasoning=="high"` 的子集像真的（25% vs 默认 11%），glm-5.3 天生像 Claude 并非错标，并修掉 284 条错标（gemini-3.5-flash-lite→3.6-flash 121 等）。
- 声称增益：未量化（数据保真度修正在其 v9 消融里对应 +0.01~+0.02 量级，但未单独给数）。
- 来源：https://www.kaggle.com/competitions/name-that-llm/discussion/752766 ；数据 https://www.kaggle.com/datasets/crtproduction/name-that-llm-open-pool
- 复现成本：纯 CPU，<1 小时（224k 段 TF-IDF 打分 + 5 折）。

**8. 两阶段 LoRA + 多层 readout 多样性**
- 技术点：Qwen2.5-14B 取前 32/48 层、关 final norm，LoRA r16/α32（q,k,v,o,gate,up,down），对第 3/5/8/11/16/21/27/32 层做 mean-pool + 逐层 LayerNorm，接 plain head 与 prompt-centred head，batch 用同 prompt 答案三元组；Stage1 在 120k 池上 1 epoch，Stage2 在官方 train 上 2 epoch，5 折按 prompt 分组。
- 声称增益：单成员 OOF 0.569→0.605（5 折 0.617/0.601/0.606/0.600/0.604）；但融合后 public LB 0.651→**0.647（−0.004）**——成员更强却更同质。另一条线（751871）证明单层 vs 8 层 readout 分数相同但 29% 判定不同，融合 **+~2 点**。
- 来源：https://www.kaggle.com/competitions/name-that-llm/discussion/753177 ；代价见 https://www.kaggle.com/competitions/name-that-llm/discussion/751871
- 复现成本：作者环境 **2.3 H100 小时/成员**；折算 T4x2 约 8–10 小时/成员，5 折+全量拟合 ≈ 45–55 小时，**会撞穿你们每周 30 小时配额**——只能减到 2–3 折或减层数。

**9. GLM 似然的算力经济学：IQ3_XXS 分段权重 + 只算 top 15–30%**
- 技术点：用 jamesliebel 公开的 GLM-5.3-Flash（117 GB）与 GLM-5.3（278 GB）IQ3_XXS 分段 GGUF，在 2×T4 上"一次只驻留一个 layer segment"流式跑真模型（llama.cpp b12247 + 补丁），每段只取前 160 token，且只对 GLM mass 最高的 15%（早期版本）或 30%（0.716 版）文本计算。
- 声称增益：把该阶段挂上去约 **+0.009~+0.012**（0.680→0.689；graft 到 0.684 stack → 0.694/0.696）。
- 来源：https://www.kaggle.com/code/estopadilla/0-689-real-glm-5-3-likelihood-on-2xt4 ；权重 https://www.kaggle.com/datasets/jamesliebel/glm53-iq3xxs-segs-a-mirror
- 复现成本：单次 run 的似然阶段 50 分钟–2 小时（1,200 段排练实测 Flash 908 s、GLM-5.3 2,057 s）；开发调试约 3–5 GPU 小时。
